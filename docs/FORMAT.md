# dsh-memory-scaffold FORMAT v1 (locked; originally dsh-self)

Status: **format v1 is locked**. This document is the human-readable contract;
`lib/format.js` is the canonical implementation. Third-party plugins that want to
interoperate with dsh-memory-scaffold memory directories must follow this document.

The point of the lock is compatibility, not control: the layout, field names and
enum values are fixed so that independent tools can read and write the same
memory without a negotiation protocol. There is no encryption, no hidden marker
and no exclusivity logic — everything here is plain markdown/JSON you can read,
diff, edit and migrate with any editor.

---

## 1. Encoding and line endings

- UTF-8, **without BOM**.
- `LF` (`\n`) line endings. Parsers tolerate `CRLF`; writers should emit `LF`.
- No file contains executable content. Memory is data, never instructions.

## 2. Directory layout

Everything lives under the memory root (`memory/` in the workspace by default):

```
<memory>/
├── hot/
│   └── state.md                     # layer 1: hot state (instinct + situation)
├── index.md                         # layer 3: trigger -> pointer
├── judgments.md                     # layer 3: judgment index (one row each)
├── judgments-cards.md               # layer 4: full judgment cards
├── QUICKSTART.md                    # human onboarding, generated by init
├── handoffs/
│   ├── handoff-YYYYMMDD-HHmmss.md   # continuation package
│   └── handoff-YYYYMMDD-HHmmss.json # machine-readable sidecar
└── .dsh-self/
    └── manifest.json                # format/template version + counters
```

The paths above are part of the lock. `handoffs/` may be empty; the remaining
files are created by `init`. A memory directory is "initialized" when
`.dsh-self/manifest.json` exists **or** at least one of the three
markdown layers exists (tools then proceed with warnings for missing files).

## 3. Template marker and versioning

Every template file starts with an HTML comment on the first lines:

```html
<!-- dsh-self template=v1.0.0 format=1 -->
```

- `template` is the **template version** (what `init` copied / the CHANGELOG
  entry a user should read before merging).
- `format` must equal `FORMAT_VERSION` (currently `1`).
- `init` records the template version in `manifest.templateVersion`.
- Upgrading the package does not rewrite user files. `review` warns
  `TEMPLATE_UPGRADE_AVAILABLE` when `manifest.templateVersion` differs from the
  package's current template version; the user merges changes manually per
  `CHANGELOG.md`.

## 4. `hot/state.md`

Content is free-form markdown; the lock is the **size metric** and the
recommended content bands (instinct / situation / next step), not the wording.

Locked metric (`hot.chars` / `hot.bytes` in `review --json`):

- `hot.bytes` = UTF-8 byte length of the whole file.
- `hot.chars` = number of non-whitespace Unicode code points after removing all
  HTML comments (`<!-- … -->`). Markdown syntax counts.
- Default limits (from `manifest.settings`): `hotMaxChars = 800`,
  `hotMaxBytes = 2048`. Exceeding either produces a warning in `review`.
- "Pending" detection is heuristic: lines that are not blockquotes or headings
  and match `- [ ]`, `TODO`, `FIXME`, `pending`, `待办`, `下一步`, `未完成`,
  `待定`, `待补` are reported as not-yet-persisted items. This is advisory; the
  format does not store tasks separately.

## 5. `index.md` — trigger → pointer

Exactly one markdown table with these columns, in this order:

```
| trigger | pointer | note |
```

- `trigger`: short trigger phrase (single line).
- `pointer`: where to look. One or more paths separated by `；` or `;`
  (each token is checked separately). For each token:
  - a path relative to the **workspace root first, then the memory root**
    (for example `memory\judgments.md`, `QUICKSTART.md`, `../docs/design.md`);
  - an absolute path;
  - a URL (`http://`, `https://`, `mailto:`), which is never checked;
  - `-` when there is no pointer yet.
  Before resolving, trailing annotations `（…）`/`(…)`, a trailing
  `第 N–M 行`, and surrounding whitespace are stripped. A wildcard token
  (`*`/`?`) is considered valid when its parent directory exists. Tokens that do
  not look like a path (no separator, no file extension — for example
  `各自 RULES.md` or `最新 HANDOFF`) are treated as informal notes and are not
  reported as broken.
  An `#anchor` suffix is stripped before the existence check.
- `note`: free short text (single line).
- `review` reports `broken_pointer` for pointer tokens whose paths do not exist.
- Table rows are written contiguously. Parsers tolerate a blank line between
  rows (hand-edited files), but writers MUST NOT introduce one.
- A legacy Chinese header `| 触发 | 指针 | 说明 |` is also accepted (fallback).

## 6. `judgments.md` — judgment index

Exactly one markdown table with these columns, in this order:

```
| id | conclusion | boundary | source | status | card | updated |
```

- `id`: `J` followed by at least three digits (`J001`, `J010`, `J1000`).
  Numbers are monotonically increasing; `judge` uses max+1.
- `conclusion`: one-line conclusion (≤300 characters; newlines are normalized
  to spaces by the writer).
- `boundary`: short boundary / failure / counterexample (default:
  `见卡（judgments-cards.md）`).
- `source`: provenance pointer — file path, URL, or `source + date`
  (≤500 characters).
- `status`: one of the locked enum values. Chinese aliases are normalized on
  read (`候选` → candidate, `常用` → common, `本能` → instinct, `降级`/`反驳`
  → refuted, `归档`/`存档` → archived); a status cell that contains extra
  information after `｜`/`|` is normalized from the first segment, and unknown
  Chinese variants starting with `降级` map to `refuted`:
  - `candidate` — captured, not yet digested (default for new rows);
  - `common` — used repeatedly, should have a card;
  - `instinct` — internalized, safe to inject every turn;
  - `refuted` — contradicted by evidence, kept for the history;
  - `archived` — retired but retained.
- `card`: `yes` when a matching card exists, `no` otherwise; a card ID (for
  example `J005`) is also accepted. `judge` always writes `yes`.
- `updated`: `YYYY-MM-DD`.
- Cell escaping: `|` → `\|`, `\` → `\\`. Values are single-line.
- The table is located by its header cells (order matters, spacing does not).
- Writers append new rows immediately before the marker
  `<!-- dsh-self:v1:judgments:end -->` when present; otherwise after the
  last table row. A missing locked header is a format error — never guess.

Machine markers:

```
<!-- dsh-self:v1:judgments:begin -->
| id | conclusion | boundary | source | status | card | updated |
| --- | --- | --- | --- | --- | --- | --- |
<!-- dsh-self:v1:judgments:end -->
```

HTML comments are documentation. Parsers MUST ignore content inside comments
(the shipped templates carry an example row in a comment — it is not data).

## 7. `judgments-cards.md` — judgment cards

A card is a level-2 heading plus five locked fields:

```markdown
## J001 <conclusion as the card title>
- why: <为什么 it holds>
- failure: <失败 / 反例 / 边界>
- unfinished: <未完成 — what is still unresolved>
- source: <来源 pointer>
- scene: <when to use — optional>
- created: 2026-01-01
- updated: 2026-01-01
```

- Field names are locked and lowercase: `why`, `failure`, `unfinished`,
  `source`, optional `scene`, system fields `created`, `updated`.
- Chinese labels are accepted on read and mapped to the locked names:
  `为什么`/`原因`/`理由` → `why`; `失败`/`失败/反例`/`失败/边界`/`反例`/`边界`
  → `failure`; `未完成`/`待完成` → `unfinished`; `来源`/`源`/`来源指针` →
  `source`; `场景` → `scene`; `创建`/`创建时间` → `created`;
  `更新`/`更新时间` → `updated`. Both `- why: …` and `- **为什么**：…`
  (Chinese colon too) are parsed; unknown labels are ignored.
- Required: `why`, `failure`, `unfinished`, `source`, `created`, `updated`.
  `scene` is optional and omitted when empty.
  **Legacy exception:** when the matching judgment row already carries a
  non-empty `source`, a card without its own `source` field is considered
  complete (hand-written libraries keep the source in `judgments.md`).
- Field values are single-line; newlines are normalized to spaces by the writer.
  `|` needs no escaping here (this is not a table).
- The heading title is the judgment conclusion, verbatim.
- Cards live between the markers `<!-- dsh-self:v1:cards:begin -->` and
  `<!-- dsh-self:v1:cards:end -->` when those exist; writers insert
  before the end marker, otherwise append at end of file.
- A card with an empty or placeholder (`待补`, `TODO`, `（空）`, …) required field
  is reported as `incomplete_card`; a card without a table row is
  `orphan_card`; a row with `card: yes` and no card is `missing_card`.

## 8. `.dsh-self/manifest.json`

Machine-readable version and counters. Schema (all fields required unless noted):

| Field | Type | Meaning |
| --- | --- | --- |
| `schema` | string | Always `"dsh-self/memory"`. |
| `formatVersion` | number | Always `1` in this release. Tools refuse unknown versions. |
| `templateVersion` | string | Semver of the scaffold templates copied at init. |
| `createdAt` / `updatedAt` | string | ISO-8601 timestamps. |
| `lang` | string | `"zh"` or `"en"`; language of generated docs/handoffs. |
| `memoryDir` | string | Memory directory as shown to the user (relative or absolute). |
| `generator` | object | `{ "name": "dsh-self", "version": "<package>" }`. |
| `layers` | object | `{ "hot", "index", "judgments", "cards" }` locked relative paths. |
| `handoffsDir` | string | Locked `"handoffs"`. |
| `counters` | object | `{ "judgment": <n>, "handoff": <n> }` last written counts. |
| `counters.lastJudgmentId` | string (optional) | Highest ID written. |
| `lastHandoffAt` / `lastHandoffPath` | string (optional) | Latest handoff info. |
| `settings` | object | Size limits and context budget (see below). |
| `lastToolVersion` | string (optional) | Last package version that touched the manifest. |

`settings`:

| Key | Default | Meaning |
| --- | --- | --- |
| `hotMaxChars` | `800` | Warning threshold for `hot.chars`. |
| `hotMaxBytes` | `2048` | Warning threshold for `hot.bytes`. |
| `contextBudgetChars` | `32000` | Characters used for the context-share estimate. |
| `contextShareNoticePercent` | `3` | Share above this is `notice`. |
| `contextShareWarnPercent` | `10` | Share above this is `warning`. |

Writers may add fields; readers MUST ignore unknown fields. Changing or removing
a field requires a new `formatVersion`.

## 9. Handoff package

### 9.1 Markdown file

Filename pattern (in `handoffs/`): `handoff-YYYYMMDD-HHmmss.md` (local time;
`--out` may override the path). Sections, in order:

1. header: `generated_at`, tool/template/format versions, stats, read order;
2. state snapshot: verbatim `hot/state.md`;
3. judgment index: `id | conclusion | status | source` — **only common/instinct rows are
   expanded**; candidates are counted (`- candidate_rows: N`) to keep the package bounded;
4. judgment cards: `### <id> <title>` plus card fields — only cards of expanded
   (common/instinct) judgments; the rest are counted (`- other_cards: N`);
5. **session decisions**: entries from `decisions.md` (title + decision/why/status fields);
   when the file has no entries the section says so — an empty file is not "no decisions",
   it is "not written down";
6. unfinished / not-yet-persisted items;
7. eight verification questions;
8. replay questions generated from top judgments;
9. **validation record**: machine checks (hot size vs limits, judgment/card parse status,
   format issues, warning codes, "no human sign-off" note);
10. honest discontinuity note and handoff history — unread/unverified content must be marked
   `UNKNOWN`, never invented.

The question texts are not part of the lock (they may be improved in a minor
release); their **count (8)** and position are.

### 9.2 JSON sidecar

Same path with `.json`. Schema: `"schema": "dsh-self/handoff"`, plus:

```
formatVersion, templateVersion, toolVersion, generatedAt, lang, memoryRoot,
stats { hotChars, hotBytes, judgments, cards, indexEntries, pending },  // pending = raw item count
hot { chars, bytes, lines, text },
judgments [ { id, conclusion, boundary, source, status, card, updated } ],
cards [ { id, title, fields { ... } } ],
index [ { trigger, pointer, note } ],
validation { hotWithinLimits, judgmentsFormatIssues, warningCodes },
pending [ { type, detail, ... } ],          // may be aggregated (count/sample)
pendingTotal,                               // raw pending item count
verificationQuestions [ 8 strings ],
replayQuestions [ strings ],
readOrder [ strings ]
```

Additive fields are allowed; consumers must tolerate unknown fields and must not
assume this sidecar exists for hand-authored packages.

## 10. Compatibility rules

**Readers must:**

- resolve files by the locked layout, not by scanning for similar names;
- parse tables by locked header names (positional after header match);
- ignore HTML comments and unknown extra columns/fields;
- gate on `manifest.formatVersion` and report unsupported versions instead of
  guessing;
- treat a missing optional field as absent, never as an error.

**Writers must:**

- never rename, reorder or add columns in a v1 table;
- never add status enum values or rename card fields in v1;
- never move or rename locked files;
- append only: do not rewrite rows/cards the writer did not create;
- never write into a legacy 5-column judgment table (read-only compatibility);
- emit UTF-8 + LF and single-line values with the escaping rules above;
- bump `FORMAT_VERSION` for any breaking change and ship a migration note in
  `CHANGELOG.md` and `docs/`.

**Extension policy:** a new optional field in `manifest.json` or the handoff
sidecar, a new file under `.dsh-self/`, or a new optional card field is
additive (allowed in a minor release). New statuses, new columns, changed ID
format or changed marker text are breaking (require format v2).

## 11. Legacy compatibility (read tolerance)

These tolerances let the tool read old or hand-written libraries; they do not
change what writers emit under format v1.

- **5-column judgments table.** A header of
  `| id | 判断 | 边界/反例 | 来源 | 状态/上次用 |` is accepted as a legacy
  judgment table: rows are read with `card: ''` and `updated: ''`, and Chinese
  statuses are normalized. Writing (`judge`) into such a table is refused with
  error code `LEGACY_FORMAT_READ_ONLY`; upgrade the header to the locked seven
  columns first (add `card` and `updated`; old rows get empty cells).
  `review` and `handoff` read it normally.
- **Chinese statuses.** See §6. Only the five English enum values are written.
- **Chinese card labels and source inheritance.** See §7.
- **Multi-pointer index cells, annotations and informal pointers.** See §5.
- **Missing manifest.** A memory directory without
  `.dsh-self/manifest.json` is still readable. Generated JSON reports
  `templateVersion: null` and `review` warns `MANIFEST_MISSING`; this is not an
  error.
- **Unknown tables are never guessed.** If neither the locked nor the legacy
  header is found, readers report an empty table and `review`/`judge` report a
  format error.

## 12. Privacy

The format stores whatever the user writes — plain text, unencrypted. Tools
never add secrets or network calls. Users should not store passwords, tokens or
identity numbers, only pointers to where secrets live, and should decide
deliberately whether to commit a memory directory to git.
